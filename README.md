# External Link Manager

Добавляет внешним ссылкам `target="_blank"` и `rel="nofollow"`, а ссылкам,
открывающимся в новой вкладке, — `noopener`. Внутренние ссылки и домены из
списка исключений не изменяются.

Версия 2.5.1. Требуется WordPress 7.0+, PHP 8.0+.

## Что делает плагин

Ссылка считается внешней, если её хост отличается от хоста сайта. Хост
сравнивается без учёта регистра, порта, завершающей точки и приставки `www.`:
`Example.com`, `example.com:8080`, `example.com.` и `www.example.com` — это
один и тот же сайт.

| Что | Как |
|---|---|
| `target="_blank"` | добавляется внешним ссылкам, если включена настройка «Открывать в новом окне» |
| `rel="noopener"` | добавляется каждой внешней ссылке, которая открывается в новой вкладке, — в том числе если `target="_blank"` стоял в тексте записи изначально |
| `rel="nofollow"` | добавляется внешним ссылкам, если включена настройка «Добавлять rel="nofollow"» |
| Существующий `rel` | сохраняется: `rel="sponsored"` останется, `nofollow` и `noopener` добавятся к нему без дублей |
| Внутренние ссылки | не изменяются |
| Относительные ссылки, якоря, `mailto:`, `tel:`, `javascript:` | не изменяются |

`noopener` добавляется всегда, когда ссылка открывается в новой вкладке: без
него страница-получатель может управлять вкладкой, с которой пришёл
посетитель. Поэтому отключение обеих настроек не убирает `noopener` у ссылок,
где `target="_blank"` уже стоит.

Параметр `noreferrer` плагин не добавляет: он скрывает Referer и меняет
поведение аналитики и партнёрских ссылок, а для защиты от доступа через
`window.opener` достаточно `noopener`.

## Где применяется

Плагин обрабатывает уже отрендеренный HTML в фильтрах:

- `the_content` — контент записи и страницы;
- `the_excerpt` — отрывок;
- `comment_text` — текст комментария;
- `widget_text_content` — текст виджета;
- `term_description` — описание рубрики, метки или термина.

Обработка происходит только при выводе. В базе данных контент не меняется,
поэтому отключение плагина сразу возвращает ссылки в исходный вид. REST API и
фиды отдают тот же отрендеренный HTML, что и страница, — это штатное поведение
фильтров WordPress. Админка и редактор блоков не затрагиваются: при
сохранении записи ссылки не переписываются.

Плагин использует `WP_HTML_Tag_Processor` (WordPress 6.2+). Если класс
недоступен, контент возвращается без изменений.

## Домены-исключения

Страница «Настройки → Внешние ссылки», вкладка «Исключённые домены». Одна
запись — один домен; можно вводить полный URL, плагин оставит только хост.
Несколько записей разделяются переносом строки, запятой или точкой с запятой.

Правила совпадения:

- `example.com` исключает сам домен и все его поддомены: `www.example.com`,
  `sub.example.com`, `cdn.example.com`;
- `notexample.com` не исключается записью `example.com` — сравнение идёт по
  границе домена, а не по подстроке;
- регистр, порт, путь и завершающая точка отбрасываются: `HTTPS://WWW.Example.com/path`
  сохранится как `example.com`;
- пустые строки игнорируются;
- если в записи указан поддомен, он покрывает только себя и свои поддомены:
  `cdn.example.com` не исключает `www.example.com`.

Поддомены домашнего хоста, кроме `www.`, считаются внешними: ссылка с
`blog.example.com` на `example.com` — внешняя, пока `blog.example.com` не
добавлен в исключения. Это сделано намеренно: плагин не угадывает, какие
поддомены относятся к сайту.

Для IDN-доменов при наличии расширения `intl` `пример.рф` и
`xn--e1afmkfd.xn--p1ai` считаются одним хостом. Без `intl` сравнение
буквальное, и такая ссылка может получить `nofollow` — это безопасный
режим, а не ошибка.

## Настройки

| Настройка | Опция | По умолчанию |
|---|---|---|
| Открывать внешние ссылки в новом окне (`target="_blank"`) | `elm_target_blank` | включено |
| Добавлять `rel="nofollow"` | `elm_nofollow` | включено |
| Домены-исключения | `elm_excluded_domains` | пусто |

## Установка

1. Скопировать каталог `external-link-manager` в `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины».
3. При необходимости настроить параметры в «Настройки → Внешние ссылки».

Плагин не создаёт таблиц в базе данных и не требует правки темы.

## Обновление

Плагин обновляется из GitHub через штатный экран «Обновления» WordPress:
источник — релизы и теги репозитория [Gnoztis/external-link-manager](https://github.com/Gnoztis/external-link-manager).
Берётся наибольшая версия из последнего релиза и самого нового тега
`X.Y.Z` / `vX.Y.Z`; пакет скачивается только по `https` с доменов GitHub.
Проверка кэшируется на шесть часов.

В строке плагина на странице «Плагины» есть ссылка «Проверить обновления» —
она сбрасывает кэш и запускает проверку заново.

### Токен GitHub (необязательно)

Без токена GitHub разрешает 60 запросов в час на IP-адрес. Если на одном
хостинге несколько сайтов и плагинов проверяют обновления, лимит может
исчерпаться, и проверка временно перестанет работать — в списке плагинов
появится сообщение «проверка не удалась: 403 (лимит GitHub API)». С токеном
лимит — 5000 запросов в час.

Токен не обязателен для публичного репозитория, но полезен на общем хостинге.
Задайте его в `wp-config.php`:

```php
define( 'ELM_GITHUB_TOKEN', 'github_pat_...' );
```

Подойдёт fine-grained token с доступом к репозиторию
`Gnoztis/external-link-manager` и правом **Contents: Read**; classic token —
с областью `public_repo`. Токен отправляется только на домены GitHub и нигде
не выводится в интерфейсе.

## Интеграция с темой WPCommunity

Дополнительные возможности включаются только тогда, когда активна тема
WPCommunity (`get_template() === 'wpcommunity'`, дочерние темы тоже
подходят). На любой другой теме плагин работает как раньше, а вкладка
PRO-пользователей отсутствует.

- **PRO-авторы.** Если у автора записи активна платная подписка PRO, внешние
  ссылки в его записях не получают `rel="nofollow"`. `target="_blank"` и
  `rel="noopener"` остаются: это безопасность, а не SEO.
- **Проверка при рендере.** Статус проверяется в момент вывода записи, а не
  сохраняется в контенте. Когда подписка заканчивается, `nofollow`
  возвращается во всех статьях автора автоматически — без фоновых задач,
  переиндексации и повторного сохранения записей.
- **Один автор.** WordPress хранит одного автора записи — `post_author`.
  Политика принадлежит владельцу контента, а не тому, кто отредактировал
  запись, и не зрителю. Если автор удалён или `post_author` равен 0, работает
  обычное поведение: `nofollow` остаётся. Co-Authors Plus намеренно не
  поддерживается: без явной поддержки такая запись получает `nofollow`.
- **Вкладка «PRO-пользователи»** (только на теме WPCommunity и только для
  `manage_options`) показывает активных PRO-пользователей: имя со ссылкой на
  профиль, дату окончания подписки и число опубликованных записей. E-mail не
  выводится. По 20 пользователей на страницу, алфавитный порядок. Список
  кэшируется на пять минут и обновляется автоматически при открытии вкладки,
  когда кэш устарел. Под таблицей выводится источник данных (`membership`,
  `missing` или `error`) для диагностики.
- **Проверка статуса.** Единственный источник — публичный метод темы
  `Membership::is_member()`. Плагин не читает user meta `expired` и опции
  темы. Если тема, класс или контейнер недоступны, а также при любой ошибке
  считается, что PRO нет (fail closed): `nofollow` остаётся. Результат можно
  переопределить фильтром `elm_user_is_pro`; без темы WPCommunity фильтр не
  вызывается — дополнительный функционал выключен.

  Контракт фильтра:

  ```php
  apply_filters( 'elm_user_is_pro', bool $is_pro, int $user_id, string $source )
  ```

  `$is_pro` — встроенный результат после fail-closed проверки; `$user_id` —
  автор записи, которая рендерится; `$source` — `membership`, `missing`,
  `error` или `filter`, только для диагностики, на поведение не влияет.
  Значение приводится к `bool`, исключение внутри callback-а перехватывается
  и трактуется как `false` (сломанный фильтр не может снять `nofollow` на
  всём сайте). Проверка выполняется один раз на пользователя за запрос.

  Примеры:

  ```php
  // 1. Другая система подписок вместо темы: WooCommerce Memberships.
  add_filter( 'elm_user_is_pro', function ( bool $is_pro, int $user_id, string $source ): bool {
      return function_exists( 'wc_memberships_is_user_active_member' )
          && wc_memberships_is_user_active_member( $user_id, 'pro' );
  }, 10, 3 );

  // 2. Точечное исключение: подписка возвращена, но в теме ещё активна.
  add_filter( 'elm_user_is_pro', function ( bool $is_pro, int $user_id, string $source ): bool {
      return 42 === $user_id ? false : $is_pro;
  }, 10, 3 );

  // 3. Аварийное отключение поблажки, если тема сломалась.
  add_filter( 'elm_user_is_pro', '__return_false' );
  ```

  В третьем примере `nofollow` остаётся у всех, включая активных PRO: это
  безопасный откат к поведению без интеграции.
